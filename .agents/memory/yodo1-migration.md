# Yodo1 MAS migration (replaces AdMob mediation on Android)

The Android ad stack is migrating off `react-native-google-mobile-ads` (RNGMA / GMA 25.x) + its AdMob mediation waterfall **to the Yodo1 MAS Full SDK**. Chosen approach: a **phased, dormant foundation** — Phase 1 lays all native infra switched OFF so the current RNGMA build is unchanged; Phase 2 flips it on, removes RNGMA, and rewires the JS (`context/AdContext.tsx`, banner UI).

## The dormancy rule (the non-obvious lesson)
**A build-environment change is NOT dormant just because no dependency consumes it yet.** Injecting vendor Maven repos, or setting `android.enableJetifier` / `android.enableDexingArtifactTransform`, alters the Gradle resolution/dexing pipeline of the *current* build even with zero Yodo1 deps present. So for a truly inert Phase 1, gate ALL of these behind the phase switch — do not "pre-stage" them.

**Why:** an architect review flagged that pre-writing those gradle.properties + repos broke the "current .aab unchanged" contract. **How to apply:** the config plugin (`plugins/withAndroidConfig.js`) has ONE `YODO1_ENABLED` constant (false in Phase 1). While false it injects no vendor repos and writes only a `yodo1Enabled=false` marker property (no AndroidX/dexing flags). Flipping it to true in Phase 2 turns on repos + props + the real module in lockstep.

## Native-module gating pattern (managed Expo, newArch, android/ gitignored)
The new SDK lives in a **local Expo module** (`modules/yodo1-mas/`, Kotlin), NOT in MainApplication — the app is managed/newArch and `android/` is regenerated by prebuild. The module's `android/build.gradle` reads the `yodo1Enabled` gradle property and uses `sourceSets` to compile EITHER a no-op stub (default, pulls zero deps) OR the real bridge, and `api()`s the Yodo1 deps only when enabled. There is intentionally no `src/main/java` (avoids a duplicate-class collision between the two `Yodo1MasModule.kt`). A library module sets `namespace` in build.gradle and needs no AndroidManifest (mirrors the sibling `modules/unity-ads`).

The JS wrapper (`index.ts`) is identical in both phases: `requireOptionalNativeModule` (null off-Android / web / Expo Go) + an `isAvailable()` probe so the stub reports false and every consumer no-ops. The real Yodo1 Kotlin (`src/yodo1/`) is written to Yodo1's published 4.x API but is **uncompilable in the Replit sandbox** — its class/package/listener signatures MUST be verified against the bundled AAR in an EAS Android build before Phase-2 cutover.

## Phase-2 hard prerequisite
Yodo1 MAS bundles its own `play-services-ads`, which CANNOT coexist with RNGMA (GMA 25.x). **Remove `react-native-google-mobile-ads` BEFORE flipping `YODO1_ENABLED=true`**, or the build hits duplicate-class / version-conflict failures.
